# Aether Known Limitations & Technical Boundaries

## 1. Demonstrated Results vs. Architectural Targets

| Dimension | Demonstrated / Verified Result | Architectural Target / Limit |
|---|---|---|
| **Concurrent WebSocket Connections** | **100 concurrent connections** verified on Apple Silicon M4 laptop with 0 disconnects and p50 latency < 30ms. | **10,000+ concurrent connections** requires a multi-node Kubernetes cluster with kernel-tuned host nodes. |
| **Message Workload** | **5.10 msg/s sender, 25.52 events/s room fan-out** verified with 100% receipt and p50 latency 48.6ms. | High-frequency stress (>1,000 msg/s) requires dedicated benchmark load generators and distributed Redis cluster. |

---

## 2. WebRTC Calling Topology (Mesh vs. SFU)

- **Current Implementation**: Aether uses a full P2P **Mesh topology** for video and voice calls. Each participant establishes a direct WebRTC peer connection with every other participant in the room.
- **Scaling Limit**: Mesh topology scales as \(O(N^2)\) network connections and \(O(N)\) outgoing video encoding streams on the client device. It is effective for **up to 5 participants**.
- **Production Recommendation**: For rooms exceeding 5 participants, an SFU (Selective Forwarding Unit) media server such as LiveKit, mediasoup, or Janus must be integrated.

---

## 3. End-to-End Encryption & Search Privacy Boundaries

- **Confidentiality Rule**: Messages flagged with `e2e: true` are transmitted encrypted and stored in PostgreSQL as ciphertext.
- **Search Trade-Off**: To protect plaintext privacy, E2E messages are **never indexed into Elasticsearch**.
- **Client Limitation**: Search queries executed against `/api/search` return only non-E2E messages. Searching encrypted message history must occur client-side on decrypted local storage.

---

## 4. Storage Architecture (Local Volumes vs. Object Storage)

- **Compose Environment**: File uploads are stored on a local Docker named volume (`uploads_data`) mounted at `/app/uploads`.
- **Horizontal Scaling Limit**: When running multiple backend replicas across different physical nodes, a local volume cannot be shared without a network filesystem (NFS) or a Kubernetes `ReadWriteMany` (RWX) PersistentVolumeClaim.
- **Production Recommendation**: In production multi-region deployments, integrate S3-compatible cloud object storage (AWS S3, Google Cloud Storage, or MinIO) via presigned URLs.

---

## 5. Development TLS Certificates

- **Self-Signed Material**: The certificates generated by `scripts/generate-dev-cert.sh` are intended exclusively for local development and benchmarking.
- **Browser Security Warnings**: Modern browsers will display an untrusted certificate warning when accessing `https://localhost` unless the generated certificate is manually imported into the operating system's trusted root keychain.
